1. Connect this page to your repo — once

GitHub Pages alone can't save a file — there's no server behind it. So this page talks straight to GitHub's free API to save the file into your repo, and then Pages serves it. Your token is only stored in your browser, never in the site files.

How to get a free token (2 minutes)
  1. On github.com, go to Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
  2. Set it to Only select repositories and pick just this one repo.
  3. Under Repository permissions, give Contents: Read and write only. Nothing else.
  4. Copy the token, paste it above, and save. GitHub only shows it once, so keep it somewhere safe.
  5. Make the repo first, and publish Pages from it (Settings → Pages → Deploy from a branch → main → / root), or this page will say “repo not found”.

2. Upload from this page

Encrypted files are saved as name.enc. Open them with the Open button below; a direct link gives only scrambled bytes. Unencrypted files: the Pages link can take 1–2 minutes to update, and the “Raw” link works immediately.

Important: Files uploaded with “Encrypt” ticked are encrypted in your browser before they leave it (AES-256-GCM, with a key made from the site password). Without the password they can't be read, even from a direct link. Their file names and sizes are still visible, so don't put secrets in a file name. Files uploaded unencrypted, or before this option existed, can be opened by anyone who finds the link. Use a long password: anyone can try guesses against an encrypted file. Free limits: keep the site under about 1 GB, and a file under 100 MB through the API (in practice, keep uploads under about 25 MB from a phone browser).
